## Overview

Navigating a team of robots through a cluttered space is hard for two reasons: robots can collide with obstacles or with each other, and they can deadlock, stuck waiting on each other forever. Most planners handle one of these well but not both.

MRNAV splits the problem across three layers, each planning over a different time horizon:

- **Long horizon:** finds a global path around known static obstacles, so robots don't get trapped in dead ends
- **Medium horizon:** replans a smooth trajectory a few seconds ahead, avoiding moving obstacles and teammates
- **Short horizon:** a fast safety layer that checks every command right before it reaches the motors

![MRNAV system architecture: long, medium, and short horizon modules](/images/mrnav-stack.png)

## My part: the short-horizon safety layer

I implemented the short-horizon module in C++ and ROS using **safety barrier certificates**. The controller first computes the acceleration it *wants* to apply, and the safety layer replaces it with the closest acceleration that keeps the robot clear of walls, moving obstacles, and other robots. When everything is safe, it leaves the command alone.

<SafetyLayer />

Because the quadrotor controller doesn't take accelerations directly, the safety layer sits inside it, between computing the desired acceleration and converting it into thrust and motor speeds. It runs much faster than the planners above it, which is what makes it a reliable last line of defense.

Outside of simulation, I also spent time soldering and building physical robots for the lab to test on.

## Results

In simulation, eight quadrotors flew for eight hours straight through a forest with 300 moving obstacles, with no collisions and no deadlocks.

The paper also tests what happens when each layer is removed. In a maze with 200 moving obstacles, only the full stack avoided both failures:

| | Collisions | Deadlocked robots |
|---|---|---|
| **Full stack** | **0 / 142 tasks** | **0 / 8** |
| Without short horizon | 29 / 183 tasks | 0 / 8 |
| Without medium horizon | 2 / 141 tasks | 6 / 8 |
| Without long horizon | 6 / 22 tasks | 7 / 8 |

Each run lasted 300 simulated seconds, so the task counts vary: robots that deadlock stop finishing tasks. Without the long horizon, seven of the eight robots got stuck, which is why that run only got through 22.
