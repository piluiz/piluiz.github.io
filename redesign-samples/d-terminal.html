~ / projects / ooo-riscv

Out-of-Order RISC-V Processor

fall 2025 · ECE 411, UIUC · #comp-arch #risc-v #systemverilog

An eight-week capstone: a 2-way superscalar RV32IM processor with register renaming, speculation, and a split load-store queue.

The goal of this project was to design a high-performance out-of-order processor that maximizes instruction-level parallelism while maintaining correct program semantics. The core implements the full RV32IM instruction set, including multiply and divide.

architecture

We used explicit register renaming with a reorder buffer (ROB) to track in-flight instructions. Reservation stations let instructions wait for operands without holding up the rest of the pipeline. Instructions can finish out of order, but they always commit in order:

[ pipeline.gif ]

      
IF fetch · ID decode · RN rename · IS issue · EX execute · CM commit · ·· waiting
Notice addi finishes early but waits for mul to commit.

    


    
advanced features

    
    
      
  • 2-way superscalar: fetch, decode, dispatch, and retire two instructions per cycle.
    • 
      
  • Gshare branch predictor: global history combined with the branch address.
    • 
      
  • Split load-store queue: independent scheduling while preserving memory order.
    • 
      
  • Next-line prefetching on the instruction cache.
    • 
    


    
what i learned

    
Not every advanced feature works well with the others. Some combinations gave diminishing returns or created new bottlenecks that canceled out their individual benefits.
