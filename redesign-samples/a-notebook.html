Building a 2-way superscalar out-of-order RISC-V core

An eight-week capstone for UIUC's ECE 411: an RV32IM processor with register renaming, speculation, and a split load-store queue.

The goal of this project was to design a high-performance out-of-order processor that maximizes instruction-level parallelism while maintaining correct program semantics. Out-of-order execution lets the processor dynamically reorder instructions to avoid stalls and keep execution units busy.

The key challenges were managing data dependencies, handling precise exceptions, and implementing efficient speculation and recovery. The core implements the full RV32IM instruction set, including multiply and divide.

Architecture

We used explicit register renaming with a reorder buffer (ROB) to track in-flight instructions. Reservation stations let instructions wait for operands without holding up the rest of the pipeline.

Advanced features

2-way superscalar
Fetch, decode, dispatch, and retire up to two instructions per cycle.
Gshare branch predictor
Global history XOR'd with the PC to index a pattern history table.
Split load-store queue
Loads and stores schedule independently while preserving memory ordering.
Next-line prefetching
Fetches the next instruction cache line ahead of time.

What I learned

Not every advanced feature works well with the others. Some combinations gave diminishing returns or created new bottlenecks that canceled out their individual benefits.
